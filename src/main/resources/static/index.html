Bully & Ring Election Algorithms (Exp 4)

Coordinator election among active nodes: node with highest ID bullies smaller IDs and assumes Primary leadership

Algorithm Mechanics

Bully Algorithm: Node contacts all higher active IDs (electionMsg). If no higher node answers OK, it becomes Coordinator and broadcasts coordinatorMsg.
Ring Algorithm: An election token circulates the logical ring of live nodes in circular order collecting active node IDs. When the token returns to the initiator, the node with the highest ID wins and is declared Coordinator.

Simulated Crash vs Real Process Kill:
  • Simulated Crash: Node ceases outbound heartbeats and throws RemoteException on all inbound RMI calls while JVM stays alive.
  • Real Process Kill: Terminate JVM with taskkill /F /PID <pid> or kill -9 <pid>. Heartbeat timeout (> 6s) triggers Bully election failover.
  • Snapshot Rejoin: When node resumes or restarts, it retrieves a full snapshot from the Primary via RMI and rebuilds its local ledger.

Race Condition Demonstration

CyclicBarrier read-sleep-write race vs AtomicInteger synchronized updates
Race Demo Mechanism: N threads synchronize at a CyclicBarrier. Each thread reads the shared counter, sleeps for 2ms, and writes back count + 1. Without synchronization, concurrent writes overwrite each other, resulting in lost updates. The safe counter uses AtomicInteger to guarantee atomic increments.

Coordinator election among active nodes: node with highest ID bullies smaller IDs and assumes Primary leadership

How Bully Election Works

  1. Node P contacts all known nodes with higher IDs (electionMsg).
  2. If no higher node answers, P wins, becomes Primary, and broadcasts coordinatorMsg to all peers.
  3. If a higher node Q answers OK, Q starts its own election and P waits for announcement.
  4. Highest active node ID in cluster is always the elected Primary coordinator.

Failure Assumptions & Consistency Guarantees: Crash-stop failures only, at most one failure at a time, no network partitions, failure detection by heartbeat timeout. Simulated Crash vs Real Process Kill:
  • Simulated Crash: Node ceases outbound heartbeats and throws RemoteException on all inbound RMI calls while JVM stays alive.
  • Real Process Kill: Terminate JVM with taskkill /F /PID <pid> or kill -9 <pid>. Heartbeat timeout (> 6s) triggers Bully election failover.
  • Snapshot Rejoin: When node resumes or restarts, it retrieves a full snapshot from the Primary via RMI and rebuilds its local ledger.
